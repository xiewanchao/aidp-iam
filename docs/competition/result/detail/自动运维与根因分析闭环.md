# 自动运维与根因分析闭环

> 一句话定位：把 AI 从开发阶段延伸到部署、验证、日志归因和运行态反馈，让问题处理形成“发现、定位、修复、回归、沉淀”的闭环。

## TRIGGER：什么时候启用

| 场景 | 说明 |
| --- | --- |
| 发布前 | clean install、uninstall、reinstall 和完整测试 |
| 夜间白+黑 | 自动处理白天 issue |
| 测试失败 | 需要判断是代码、配置、数据还是环境问题 |
| 运维巡检 | 需要多主机采集和报告 |
| 回归验证 | 修复后自动确认核心路径是否恢复 |

## SCOPE：自动运维覆盖什么

### 覆盖

- 本地或测试环境重建。
- 健康检查。
- 自动化测试。
- 日志收集和归因。
- 低风险修复。
- 修复建议生成。
- 回归报告。

### 不覆盖

- 生产环境无审批变更。
- 破坏性数据库操作。
- 安全策略高风险修改。
- 需要敏感凭据的操作。
- 未经确认的大规模重构。

## WORKFLOW：自动运维闭环

```text
触发任务
  -> 加载环境和测试上下文
  -> 执行部署或诊断命令
  -> 收集输出和日志
  -> AI 归因分类
  -> 生成低风险修复或建议
  -> 运行回归验证
  -> 输出报告
  -> 沉淀问题和规则
```

## 根因分析协议

AI 不能停留在表面错误。必须按照以下顺序追踪：

```text
现象
  -> 请求入口
  -> 认证身份
  -> 路径策略
  -> 资源 ACL
  -> 数据初始化
  -> 配置和环境
  -> 代码逻辑
  -> 修复和回归
```

### 分类标准

| 类型 | 判断依据 | 处理方式 |
| --- | --- | --- |
| 代码 Bug | 实现与 Spec 或测试不一致 | 最小修复 + 回归 |
| 配置问题 | Helm、Gateway、Secret、路由不一致 | 修改配置 + 部署验证 |
| 数据问题 | 初始化数据、存量数据、迁移遗漏 | 生成迁移或修复脚本，需人工确认 |
| 环境问题 | 服务未启动、依赖不可达、权限不足 | 输出环境证据和人工操作建议 |
| 设计问题 | 当前 Spec 无法决定 | 停止，交给人工决策 |

## AIDP IAM 自动运维场景

### 1. clean install 验证

```text
cleanup
  -> setup
  -> test
  -> cleanup
  -> setup --skip-build
  -> test
```

目标：

- 验证全新安装可用。
- 验证卸载清理干净。
- 验证重装后鉴权状态可恢复。

### 2. Gateway 黑盒测试

验证：

- HTTPRoute 生效。
- SecurityPolicy 挂载。
- ext_authz 被调用。
- ext_proc 注入 header。
- 后端按权限过滤列表。

### 3. API Key 回归

验证：

- 创建、轮换、禁用、删除。
- allowed_paths。
- expires_at。
- API Key 进入 OPA 和 ACL。

### 4. OPA 策略验证

验证：

- path_rules 数据生成。
- OPA allow / deny。
- 应用禁用后拒绝。
- 权限组绑定生效。

## 黄区运维助手映射

运维助手把同一闭环迁移到黄区运维场景：

```text
主机信息
  -> SSH 并发采集
  -> 输出解析
  -> 领域知识注入
  -> LLM 推理
  -> SSE 展示
  -> 诊断报告
  -> 规则沉淀
```

可承接场景：

- 流控诊断。
- 一键组网。
- IO 模型分析。
- 环境信息抓取。
- CVE 周推。

## PROMPT TEMPLATES

```text

请按以下分类归因：
1. 代码 Bug
2. 配置问题
3. 数据问题

- 不要直接改代码

```

## OUTPUT ARTIFACTS

| 产物 | 说明 |
| --- | --- |
| 自动运维报告 | 部署、测试、健康状态汇总 |
| 根因分析记录 | 证据链和归因 |
| 修复补丁或建议 | 低风险可修，高风险给建议 |
| 回归结果 | 修复后测试情况 |
| 知识规则 | 可进入运维助手知识库 |

## METRICS

| 指标 | 说明 |
| --- | --- |
| 平均定位时间 | 从失败到根因分类的时间 |
| 自动归因准确率 | AI 分类是否被人工认可 |
| 自动修复成功率 | 低风险问题自动修复并回归通过比例 |
| 人工接管率 | 需要人工决策或权限的比例 |
| 规则沉淀数 | 新增运维规则或诊断卡片数量 |

## 摘要口径

> 自动运维不是让 AI 直接操作生产，而是在受控环境中把部署、测试、日志归因和报告生成自动化。AI 负责重复、系统、可回归的诊断工作，人工保留生产审批和高风险决策。
