【IAM】支持用户认证、应用注册与外部 IdP 联邦认证

1. 简要说明

基于 groups 模型实现用户认证体系，支持本地密码登录和外部 IdP 联邦认证。用户登录后获取带 groups 信息的 JWT。支持通过 License 注册和管理可用应用，配置外部企业 IdP 实现联邦认证接入。

2. Actor

管理员、普通用户

3. 前置条件

数据库和身份认证服务已部署并可访问

4. 最小保证

用户登录失败不会破坏已有数据
外部 IdP 配置错误不影响本地登录

5. 成功保证

1）用户登录后 JWT 包含 groups 字段
2）注册应用时自动创建对应管理员组
3）License 开关即时生效
4）外部 IdP 用户首次登录后自动创建本地账号并加入默认用户组

6. 触发事件

1）普通用户：发起本地登录或外部 IdP 联邦认证登录
2）管理员：注册应用或更新 License 信息
3）管理员：配置外部 IdP
4）系统事件：首次部署触发身份数据初始化

7. 主成功场景

1）普通用户输入凭证登录，系统签发包含 groups 的 JWT，用户获得访问令牌
2）管理员注册新应用，系统创建应用记录并自动生成管理员组和默认资源规则
3）管理员停用或启用应用 License，系统立即拦截或恢复该应用下所有请求
4）管理员上传 SAML Metadata，系统自动创建 IdP 实例和默认属性映射
5）普通用户通过联邦认证首次登录，系统自动创建本地账号并加入默认用户组
6）管理员删除 IdP 实例，该联邦认证入口立即失效，已有本地账号由系统自动定期清理

8. 扩展场景（包括异常场景）

•       拒绝场景：凭证无效返回认证失败、身份认证服务不可用时新用户无法登录
•       约束：N/A
•       规格：N/A
•       升级：支持滚动升级，不覆盖已有数据
•       可靠性：支持多副本部署
•       性能：N/A
•       安全：满足 JWT 签名和密码存储安全规范要求
•       韧性：身份认证服务宕机时已登录用户不受影响，恢复后自动接受新登录
•       可服务：身份认证服务恢复后自动接受新登录请求
•       可测试：N/A
•       支持的产品：A800

【IAM】支持路径级鉴权与资源访问鉴权

1. 简要说明

请求经过 Gateway 时实现两级鉴权：第一级路径级鉴权，检查应用是否启用、路径是否受保护、用户是否在允许的组中；第二级资源实例级鉴权，检查用户对具体资源的访问权限，支持子资源继承和权限-操作映射。

2. Actor

普通用户、管理员

3. 前置条件

用户请求携带有效 JWT
路径规则和资源权限数据已就绪

4. 最小保证

鉴权失败不泄露内部信息
策略引擎故障时默认拒绝，不会误放行

5. 成功保证

1）所有请求经过路径级鉴权
2）应用禁用时该应用下所有请求被拒绝
3）有资源权限的用户放行，无权限或权限不足的用户被拒绝
4）子资源操作继承父资源权限

6. 触发事件

1）普通用户：发起任意 HTTP 请求到达 Gateway
2）管理员：创建、修改或删除路径保护规则

7. 主成功场景

1）普通用户访问受保护路径，系统检查用户组与路径规则，匹配则放行，不匹配则拒绝
2）普通用户访问已停用应用的路径，系统直接拒绝
3）管理员创建或删除路径保护规则，系统在刷新周期内生效
4）用户对资源执行操作，系统按权限层级检查，权限足够则放行，不足则拒绝
5）用户访问子资源，系统自动继承父资源权限进行检查

8. 扩展场景（包括异常场景）

•       拒绝场景：JWT 无效或过期、无路径权限、无资源权限、权限不足
•       约束：N/A
•       规格：N/A
•       升级：支持滚动升级，多副本逐个重启不中断鉴权
•       可靠性：支持多副本部署
•       性能：N/A
•       安全：未授权请求不会到达后端应用、策略引擎故障默认拒绝
•       韧性：策略引擎恢复后自动接受查询
•       可服务：策略引擎恢复后自动接受查询
•       可测试：N/A
•       支持的产品：A800

【IAM】支持资源 ACL 自动同步与权限管理

1. 简要说明

在 Gateway 响应阶段自动拦截资源创建和删除响应，实现 ACL 自动同步；提供 ACL 管理 API 支持资源分享、取消分享和权限修改；通过重试队列保障 ACL 数据最终一致性。

2. Actor

普通用户、资源 owner

3. 前置条件

资源数据存在
Gateway 策略已绑定
能验证 owner 权限

4. 最小保证

ACL 写入失败时记录到重试队列，不丢失
ACL 管理组件故障不阻塞业务请求
ACL API 操作失败不影响已有权限数据

5. 成功保证

1）创建资源后自动写入 owner 权限记录
2）删除资源后该资源的所有权限记录被清除
3）分享后目标用户/组可按对应权限级别访问资源
4）修改权限后立即生效
5）撤销分享后目标用户无法访问该资源
6）所有重试记录最终被处理

6. 触发事件

1）普通用户：创建资源
2）普通用户：删除资源
3）资源 owner：调用 ACL API 分享/修改/撤销权限
4）系统事件：定时任务触发重试

7. 主成功场景

1）普通用户创建资源成功，系统自动写入 owner 权限记录
2）普通用户删除资源成功，系统自动清除该资源的所有权限记录
3）资源 owner 分享资源给目标用户/组，被分享者立即可按对应权限访问
4）资源 owner 修改或取消分享，目标用户权限立即变更或失效
5）非 owner 用户调用分享/修改/撤销接口，系统拒绝操作
6）ACL 写入故障时，失败操作进入重试队列，系统按指数退避自动重试，业务请求不受影响

8. 扩展场景（包括异常场景）

•       拒绝场景：非 owner 调用 ACL API 被拒绝、资源不存在、重复分享
•       约束：N/A
•       规格：支持最大规格，见特性内部规格
•       升级：支持滚动升级，多副本逐个重启，业务请求不中断
•       可靠性：支持多副本部署
•       性能：N/A
•       安全：ACL API 只有 owner 可操作
•       韧性：ACL 延迟同步时业务可用但权限延迟生效，恢复后自动补写
•       可服务：恢复后自动处理重试队列
•       可测试：N/A
•       支持的产品：A800

【IAM】支持资源列表过滤

1. 简要说明

在请求阶段感知分页参数，查询用户可访问的资源列表，按分页取出当前页对应的资源 ID 注入请求头，后端应用读取请求头查询业务数据并返回分页结果。实现用户只能看到自己有权限的资源。

2. Actor

普通用户、后端应用

3. 前置条件

资源权限数据已存在
Gateway 策略已绑定

4. 最小保证

列表过滤处理失败时放行请求，后端返回空列表
不会返回用户无权限的资源

5. 成功保证

1）列表结果只包含用户有权限的资源
2）分页准确，总数和当前页数据一致
3）每次注入的 ID 数量等于分页大小，不会超限

6. 触发事件

1）普通用户：发起 GET 请求访问资源集合路径

7. 主成功场景

1）普通用户请求资源列表，系统查询可访问资源 ID 注入请求头，后端返回过滤后的结果
2）普通用户翻页，系统按分页偏移注入对应 ID，后端返回正确的分页数据
3）普通用户无任何可访问资源，后端返回空结果
4）管理员请求列表，系统不注入过滤信息，后端返回全量数据

8. 扩展场景（包括异常场景）

•       拒绝场景：N/A
•       约束：N/A
•       规格：支持最大规格，见特性内部规格
•       升级：支持滚动升级，升级期间列表返回空而非报错
•       可靠性：支持多副本部署
•       性能：N/A
•       安全：不会返回用户无权限的资源 ID
•       韧性：N/A
•       可服务：服务恢复后自动恢复列表过滤功能
•       可测试：N/A
•       支持的产品：A800

【IAM】支持 API Key 认证与管理

1. 简要说明

支持外部应用通过 API Key 访问知识库、记忆库等服务。API Key 认证后转换为等效的服务账号身份，进行路径鉴权和资源鉴权流程。提供 API Key 的完整生命周期管理（创建、查看、更新、删除、轮换）。

2. Actor

管理员、API Key 应用

3. 前置条件

资源实例创建完成

4. 最小保证

API Key 授权、鉴权操作对系统无影响

5. 成功保证

1）支持 API Key 创建、删除、一次性展示

6. 触发事件

1）管理员/用户：创建 API Key
2）管理员/用户：关联 API Key 与资源

请求鉴权：
1）外部应用携带有效 API Key 请求资源，系统验证 Key 有效并转换为服务账号身份后完成鉴权，请求放行

1）管理员轮换 API Key，系统生成新 Key 并保留原有权限关联，返回新明文
