1. 简要说明

基于 groups 模型实现用户认证体系，支持本地密码登录和外部 IdP 联邦认证。用户登录后获取带 groups 信息的 JWT。支持根据 License 状态控制应用启用/禁用，配置外部企业 IdP 实现联邦认证接入。

2. Actor

管理员、普通用户

3. 前置条件

数据库和身份认证服务已部署并可访问

4. 最小保证

认证、注册操作对系统无影响

5. 成功保证

1）支持用户登录并获取包含权限信息的 JWT
2）支持应用注册，根据 License 状态控制应用启用/禁用
3）支持外部 IdP 联邦认证接入

6. 触发事件

1）普通用户：发起登录
2）管理员：注册应用
3）管理员：配置外部 IdP

7. 主成功场景

1）普通用户登录成功，系统签发 JWT，用户获得访问令牌
2）管理员注册新应用，系统创建应用记录
3）应用 License 状态变更时，系统立即拦截或恢复该应用下所有请求
4）管理员配置外部 IdP，普通用户通过联邦认证登录成功
5）管理员删除 IdP 实例，该联邦认证入口失效

8. 扩展场景（包括异常场景）

•       拒绝场景：凭证无效、身份认证服务不可用时新用户无法登录
•       约束：N/A
•       规格：N/A
•       升级：支持滚动升级，不覆盖已有数据
•       可靠性：支持多副本部署
•       性能：N/A
•       安全：满足认证安全规范要求
•       韧性：身份认证服务宕机时已登录用户不受影响，恢复后自动接受新登录

【IAM】支持路径级鉴权与资源访问鉴权

1. 简要说明

请求经过 Gateway 时实现两级鉴权：第一级路径级鉴权，检查应用是否启用、路径是否受保护、用户是否在允许的组中；第二级资源实例级鉴权，检查用户对具体资源的访问权限，支持子资源继承和权限-操作映射。

2. Actor

普通用户、管理员

3. 前置条件

用户请求携带有效 JWT

4. 最小保证

鉴权操作对系统无影响

5. 成功保证

1）支持路径级鉴权，按路径规则和用户组进行访问控制
2）支持资源级鉴权，按权限层级对资源操作进行访问控制

6. 触发事件

1）普通用户：发起业务请求
2）管理员：配置路径保护规则

7. 主成功场景

1）普通用户访问受保护路径，系统按路径规则和用户组检查，匹配则放行，不匹配则拒绝
2）管理员创建或删除路径保护规则，系统在刷新周期内生效
3）用户对资源执行操作，系统按权限层级检查，权限足够则放行，不足则拒绝

8. 扩展场景（包括异常场景）

•       拒绝场景：JWT 无效或过期、无路径权限、无资源权限、权限不足

•       规格：N/A
•       升级：支持滚动升级，多副本逐个重启不中断鉴权
•       可靠性：支持多副本部署
•       性能：N/A
•       安全：未授权请求不会到达后端应用、策略引擎故障默认拒绝

【Gateway】支持业务 IP 配置与容器网络前端集成

1. 简要说明

Gateway 作为所有业务请求的统一入口，对接容器平台提供的网络前端能力，通过多网络平面挂载机制将业务 IP 直接绑定到 Gateway 实例。支持首次部署时配置业务 IP，支持运行期变更业务 IP，支持 Pod 重建或节点故障时业务 IP 保持稳定。

2. Actor

管理员、网络管理员

3. 前置条件

容器平台已创建前端网络平面并分配可用 IP 资源
Gateway 组件镜像与部署清单已就绪

4. 最小保证

IP 配置与变更操作失败时，Gateway 可恢复至变更前状态，不影响已有路由与鉴权能力

5. 成功保证

1）支持首次部署时通过部署参数指定前端网络平面，Gateway 自动获取业务 IP 并对外可达
2）支持运行期通过修改部署参数变更业务 IP 绑定的网络平面，升级后新业务 IP 生效
3）支持 Gateway 多副本部署，每副本独立持有业务 IP
4）支持 Pod 重建与节点漂移场景下业务 IP 保持不变

6. 触发事件

1）管理员：首次部署 Gateway 时指定前端网络平面
2）管理员：运行期变更 Gateway 的业务 IP 或所属网络平面
3）系统事件：Pod 异常重建或节点故障触发漂移

7. 主成功场景

1）管理员在容器平台侧创建前端网络平面并获取标识，将该标识配置到 Gateway 部署参数；Gateway 部署后自动挂载前端与后端两个网络平面，外部通过业务 IP 访问 Gateway
2）管理员变更部署参数中的网络平面标识并执行升级，Gateway 滚动更新后绑定到新的业务 IP，外部通过新 IP 访问
3）Gateway Pod 因故障被重建或调度至其他节点，容器平台按 Pod 身份保留原业务 IP，客户端访问无感
4）Gateway 多副本部署时，每个副本分别获取独立业务 IP，支持外部通过 DNS 轮询或前置负载均衡分流

8. 扩展场景（包括异常场景）

•       拒绝场景：指定的网络平面不存在或 IP 资源耗尽时 Gateway 无法启动、部署参数格式错误导致业务 IP 挂载失败
•       约束：Gateway 需以支持稳定身份的部署形态运行，以支持业务 IP 保留；前端与后端网络平面隔离，后端网络平面不直接对外暴露
•       规格：N/A
•       升级：支持滚动升级，变更业务 IP 时逐副本切换，多副本场景下业务不中断
•       可靠性：支持多副本部署，单副本故障或漂移不影响其他副本业务 IP 可达性
•       性能：N/A
•       安全：业务 IP 仅在前端网络平面暴露，Gateway 内部管理流量走后端网络平面
•       韧性：节点故障时业务 IP 自动随 Pod 迁移至新节点
•       可服务：Pod 重建后容器平台自动恢复原业务 IP，无需人工干预
•       可测试：N/A
•       支持的产品：A800
