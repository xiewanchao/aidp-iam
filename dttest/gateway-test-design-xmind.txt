gateway-test-design-xmind
	AIDP Gateway独立测试设计
		测试设计输入：设计/开发人员/TSE串讲/交流过程
			需求背景
				分析思路
					1、客户场景分析：Gateway作为AIDP业务统一入口，需要在标准K8s集群上独立部署并完成基础路由、策略绑定、跨命名空间引用控制和业务IP对外暴露。
					2、局点信息分析：不涉及
					3、本测试方案仅覆盖Gateway两类对象：GW路由初始化类、BIP业务IP类。
				分析结果
					Gateway独立测试拆分为两组：
						GW：应用初始化与路由集成
						BIP：业务IP配置与容器网络前端集成
					测试后端采用whoami或任意HTTP echo服务，作为Gateway转发链路验证对象。
					BIP依赖平台DM和容器网络前端能力，平台内部实现不展开，只验证Gateway集成结果。
			友商竞争力分析
				分析思路
					1、对标主流K8s Gateway/Ingress能力：支持声明式路由、跨namespace授权、策略绑定、滚动升级、入口IP暴露。
					2、差异点：本方案额外关注平台前端网络平面分配业务IP、StatefulSet保IP、节点漂移保IP。
				分析结果
					不展开友商实测。
					形成黑盒验收点：一键部署可用、路由可达、未授权不转发、业务IP稳定、故障后可恢复。
			NAS协议一致性分析
				分析思路
					1、本特性为K8s Gateway与容器网络前端集成，不涉及NFS/SMB协议一致性。
					2、不涉及新增NAS报文字段、NAS命令字、主机侧NAS协议行为。
				分析结果
					不涉及NAS协议一致性测试。
			周边依赖对象分析
				分析思路
					1、外部依赖：K8s API Server、Helm、Envoy Gateway Controller、Gateway API CRD、容器网络插件、DM前端网络平面。
					2、内部依赖：GatewayClass、Gateway、EnvoyProxy、HTTPRoute、ReferenceGrant、SecurityPolicy、BackendTrafficPolicy、ClientTrafficPolicy。
					3、兼容性依赖：K8s版本、Gateway API版本、Envoy Gateway版本、业务IP暴露方式。
				分析结果
					GW测试关注K8s资源状态和HTTP访问结果。
					BIP测试关注Pod注解、业务IP绑定、Pod重建、网络平面变更和节点漂移后的业务可达。
			关键NAS测试对象分析
				测试因子提取
					分析思路
						被测对象
							Gateway控制面：Envoy Gateway Controller
							Gateway数据面：Envoy data-plane Pod/Service
							Gateway API资源：GatewayClass、Gateway、HTTPRoute、ReferenceGrant
							策略资源：SecurityPolicy、BackendTrafficPolicy、ClientTrafficPolicy
							业务IP资源：前端网络平面、Pod网络注解、业务IP绑定关系
						外部依赖
							环境组网
								平台业务IP入口
							测试后端
								whoami Deployment
								whoami Service
						内部依赖
							Gateway控制器配置同步流程
							Envoy配置下发流程
							HTTPRoute状态更新流程
							策略绑定与生效流程
						模块内部流程处理
							一键部署流程
							重复部署幂等流程
							路由创建生效流程
							跨命名空间引用授权流程
							默认拒绝流程
							业务IP分配和恢复流程
					分析结果
						测试因子：
							部署方式：首次安装、重复安装、升级
							路由类型：有效路由、无路由、路径不匹配路由
							后端引用：同namespace、跨namespace有ReferenceGrant、跨namespace无ReferenceGrant
							来源IP：白名单来源、非白名单来源、SNAT场景
							路径白名单：允许路径、未配置路径
							业务IP：首次分配、Pod重建保IP、变更网络平面换IP、节点故障漂移保IP
				规格资源项分析
					分析思路
						外部规格（客户面可见）
						内部规格（流程相关，客户不可见）
						超规格
							不存在的网络平面
							非法部署参数
						资源访问互斥能力
							升级和流量访问并发
							Pod重建和业务访问并发
							节点漂移和业务访问并发
					分析结果
				缓存专项分析
					分析思路
						本特性不直接新增业务缓存。
						Gateway配置缓存属于Envoy/Gateway Controller内部能力，黑盒仅观察配置生效和恢复。
					分析结果
						不单独设计缓存专项。
				关键流程分析
					分析思路
						模块内部时序图
							管理员执行helm安装 -> CRD创建 -> controller启动 -> GatewayClass/Gateway创建 -> Envoy data-plane启动 -> Service暴露 -> 外部访问
							创建HTTPRoute -> Gateway控制器完成配置同步 -> Envoy配置更新 -> 外部请求转发后端
							跨namespace HTTPRoute引用Service -> 检查ReferenceGrant -> 有授权放行 -> 无授权拒绝
							指定前端网络平面 -> Pod注解生效 -> 平台分配业务IP -> 外部访问业务IP
							Pod重建/节点故障 -> 平台按稳定身份恢复业务IP -> Gateway恢复可达
						MST测试覆盖
							模块功能
								对外提供的接口
									K8s API资源接口
									HTTP外部访问入口
								需要调用的接口
									K8s API Server
									容器网络前端接口
									DM网络平面配置
								模块流程
									主流程：部署、路由、业务IP可达
									异常分支：无ReferenceGrant、非白名单IP、未配置路径、Pod重建、节点漂移
							模块可靠性
								Pod重建
								节点故障漂移
								滚动升级
								策略恢复
					分析结果
						关键流程通过黑盒用例覆盖，必要时补充kubectl状态、日志和事件作为观察点。
				后台任务
					分析思路
						不涉及业务后台任务。
					分析结果
				引用计数
					分析思路
						不涉及显式引用计数。
					分析结果
						不设计引用计数专项。
				故障模式
					分析思路
						新增或相关故障模式：
							Gateway controller异常
							Envoy data-plane Pod异常
							ReferenceGrant缺失
							策略配置错误
							业务IP分配失败
							节点故障导致Pod迁移
					分析结果
						本轮覆盖Pod异常重建、节点故障漂移、未授权不转发。
				数据可靠性
					分析思路
						Gateway不持久化业务数据。
						关注配置幂等和升级不破坏已有路由。
					分析结果
						通过重复部署、滚动升级、路由继续可用验证配置可靠性。
				升级影响性
					1、该特性影响Gateway滚动升级流程。
					2、需要验证升级期间路由不中断、变更网络平面后新业务IP生效。
					分析结果
						GW覆盖幂等部署。
						BIP覆盖变更网络平面滚动升级。
				是否涉及硬件形态
					分析思路
						SR支持产品为A800。
						Gateway本身主要依赖K8s与容器网络能力，但前端网络IP创建需要前端网络卡。
					分析结果
						本轮按A800标准K8s环境验证。
				通用观察项
					分析思路
						黑盒观察项
							HTTP状态码
							whoami返回内容
							后端访问日志
							Gateway/HTTPRoute状态
							Pod Ready状态
							业务IP绑定关系
						内部观察项
							kubectl describe事件
							controller日志
							data-plane日志
							平台DM网络平面页面
					分析结果
						每个拒绝类用例必须同时检查HTTP返回码和后端日志，证明请求未到达后端。
			可测试性需求分析
				原则
					基于关键测试对象和流程可操作、可构造、可观察原则，识别测试手段。
				可测试性需求
					需要提供Gateway一键部署命令。
					需要提供whoami或等价HTTP echo后端。
					需要提供查询Gateway/HTTPRoute状态的kubectl命令。
					需要提供查询业务IP绑定关系的命令或DM页面路径。
					需要提供Pod重建和节点漂移的可控触发方式。
					需要提供保源IP方案，否则IP白名单只能做配置验证，无法做真实来源IP拦截验证。
			约束限制分析
				分析思路
					业务IP测试依赖平台网络前端能力，不是纯标准K8s即可完成。
					IP白名单依赖Gateway能够识别真实源IP。
					节点故障漂移测试涉及集群变更
				分析结果
					BIP用例标记为平台集成用例。
					节点故障优先使用cordon/drain模拟，避免破坏性操作。
			等价类分析规则
				分析思路
					按测试对象划分等价类，避免无意义组合爆炸。
				分析结果
					部署等价类：首次部署、重复部署、滚动升级。
					路由等价类：匹配路径、不匹配路径、跨namespace引用。
					授权等价类：有ReferenceGrant、无ReferenceGrant。
					来源IP等价类：白名单来源、非白名单来源。
					业务IP等价类：首次分配、重建恢复、网络平面变更、节点漂移。
		特性测试设计：基于开发串讲输入，开展多维度测试设计
			测试覆盖
				LLT测试
					推动开发覆盖Helm模板渲染、CRD schema、策略模板、业务IP参数渲染的LLT。
				MST/SFMEA活动测试
					要求开发输出Gateway部署、路由配置同步、ReferenceGrant校验、业务IP注解渲染和Pod重建恢复的SFMEA分析。
				功能测试
					SR验收
						测试思路
							逐条覆盖Gateway两个SR，拆分为GW和BIP两类。
							GW覆盖安装、初始化、路由、策略、安全负面。
							BIP覆盖业务IP分配、保IP、网络平面变更、节点故障漂移。
						SR-GW-01 【Gateway】支持应用初始化与路由集成
							关键流程分析
								一键部署流程
								重复部署幂等流程
								基础路由创建流程
								ReferenceGrant授权流程
								IP白名单策略流程
								路径默认拒绝流程
								流量/DDoS策略绑定流程
							测试因子分析
								部署
									首次安装
									重复安装
									升级安装
								路由
									有匹配路由
									无匹配路由
									跨namespace后端引用
								策略
									IP白名单
									路径白名单
									流量策略
									DDoS/限流策略
							通用观察点提取
								helm状态
								CRD数量
								controller Pod状态
								Gateway Programmed状态
								HTTPRoute Accepted状态
								HTTP状态码
								whoami后端日志
							黑盒测试覆盖
								部署初始化
									验证IAM与Gateway部署后入口地址正常暴露，Gateway外部入口和IAM服务入口均可访问
									验证IAM与Gateway使用相同参数重复部署保持幂等，入口地址和已发布业务路由不被破坏
								基础路由
									验证创建HTTPRoute后，Gateway能够将指定路径请求转发到whoami后端
									验证HTTPRoute状态为Accepted=True时，外部访问返回后端真实响应
									验证后端Service异常或不存在时，HTTPRoute状态和Gateway事件可观察到异常原因
									验证删除HTTPRoute后，原路径不再转发到后端
								ReferenceGrant跨命名空间授权
									验证跨namespace引用后端Service并配置ReferenceGrant后，请求能够正常转发到后端
									验证跨namespace引用后端Service但缺失ReferenceGrant时，请求不能到达后端
									验证删除ReferenceGrant后，已存在的跨namespace路由变为不可用
									验证重新补齐ReferenceGrant后，跨namespace路由自动恢复可用
								IP白名单
									验证配置IP白名单后，白名单来源客户端访问受保护路径成功
									验证非白名单来源客户端访问受保护路径被Gateway拒绝，后端无访问记录
									验证IP白名单策略删除后，基础路由访问恢复到无白名单限制状态
									验证入口无法保留真实源IP时，IP白名单场景记录为环境约束并切换保源IP入口重测
								路径白名单和默认拒绝
									验证仅配置白名单路径时，白名单内路径访问成功
									验证白名单外路径访问被拒绝或返回404，后端无访问记录
									验证未知路径访问默认拒绝，不被转发到任意后端
									验证新增白名单路径后，新路径在配置同步完成后可访问
								OMS日志上传对接
									验证Gateway日志对象可在OMS页面自动出现并可发起收集
									验证Gateway日志收集完成后按日志对象分别生成zip包并上传到OMS目录
									验证Gateway日志收集进度和文件名可在OMS页面正常展示
									验证IAM日志对象可在OMS页面自动出现并可发起收集
									验证IAM日志收集完成后按日志对象分别生成zip包并上传到OMS目录
									验证IAM日志收集进度和文件名可在OMS页面正常展示
						SR-BIP-01 【Gateway】支持业务IP配置与容器网络前端集成
							关键流程分析
								DM创建前端网络平面
								部署参数指定网络平面标识
								Pod YAML增加平台网络注解
								Pod启动后自动分配业务IP
								外部通过业务IP访问Gateway
								Pod重建后业务IP恢复
								变更网络平面后滚动升级新IP生效
								节点故障后业务IP随Pod漂移
							测试因子分析
								网络平面
									原前端网络平面
									新前端网络平面
								Pod形态
									StatefulSet稳定身份
									重建Pod
									漂移Pod
								业务IP
									首次分配
									保持不变
									变更生效
									漂移可达
							通用观察点提取
								DM前端网络平面状态
								Pod注解
								Pod所在节点
								业务IP绑定关系
								curl业务IP结果
								Pod重建前后业务IP对比
								节点漂移前后业务IP对比
							黑盒测试覆盖
								前端网络平面首次集成
									验证DM创建前端网络平面后，Gateway部署参数指定该网络平面可正常部署
									验证Gateway Pod YAML包含平台要求的前端网络注解后，Pod启动自动获取业务IP
									验证业务IP与Gateway Pod绑定关系可在平台或K8s资源中查询
									验证外部通过业务IP访问Gateway基础路由成功
									验证业务IP仅作为前端网络入口暴露，后端网络平面不直接对外暴露
								Pod异常重建保IP
									验证Gateway Pod删除重建后，重建后的Pod继续持有原业务IP
									验证Gateway Pod异常重建后，外部通过原业务IP访问基础路由恢复正常
									验证多副本场景下单个Gateway Pod重建，不影响其他副本业务IP可达
									验证Pod重建过程中业务IP恢复无需人工重新绑定
								变更网络平面滚动升级
									验证Gateway从原前端网络平面变更到新前端网络平面后，滚动升级成功
									验证滚动升级完成后Gateway绑定新网络平面的业务IP
									验证外部通过新业务IP访问Gateway基础路由成功
									验证旧业务IP不再作为当前Gateway入口
									验证变更网络平面失败时，Gateway可恢复或保持变更前业务IP入口能力
								节点故障漂移
									验证Gateway Pod所在节点故障或受控驱逐后，Pod可调度到新节点
									验证Gateway Pod迁移到新节点后，原业务IP保持不变
									验证节点漂移后外部通过原业务IP访问Gateway基础路由成功
									验证恢复故障节点后，Gateway业务IP访问保持正常
								异常场景
									验证指定不存在的前端网络平面时，Gateway无法获取业务IP且错误可观察
									验证前端网络平面IP池耗尽时，新增Gateway实例无法获取业务IP且已有实例不受影响
									验证Pod网络注解格式错误时，业务IP挂载失败且错误可观察
									验证变更到不可用网络平面失败时，已有路由和原业务IP入口不被破坏
							MST测试
								验证网络平面不存在时Gateway Pod无法获取业务IP且错误可观察
								验证IP池耗尽时新增Pod无法获取业务IP且已有Pod不受影响
								验证Pod注解格式错误时业务IP挂载失败且错误可观察
								验证滚动升级中持续访问业务IP，观察业务是否中断
					特性正交
						测试思路
							Gateway与K8s Service、HTTPRoute、策略资源、容器网络前端存在交互。
						测试覆盖
							保留Gateway与业务IP、Gateway与策略、Gateway与ReferenceGrant正交。
					协议一致性
						测试思路
							不涉及NAS协议一致性。
						测试覆盖
							不涉及。
					友商搬迁
						测试思路
							不涉及数据搬迁。
						测试覆盖
							不涉及。
					典型测试模式
						模式分析
							管控面（K8s API/Helm/DM）
								关注声明式配置、幂等、错误可观察。
							入口转发
								关注外部请求到Gateway再到后端的完整链路。
							故障恢复
								关注Pod重建、节点漂移、滚动升级。
						测试覆盖
							已在GW和BIP黑盒测试中覆盖。
					防护网
						基于SR覆盖完整性原则，建议后续将Gateway首次部署、基础路由、ReferenceGrant正反向、路径默认拒绝场景加入自动化防护网。
				DFX测试
					规格压力
						测试思路
							本轮不做满规格压测，保留轻量并发和策略限流验证。
						测试覆盖
							验证限流策略达到阈值后触发限流或拒绝响应。
					可靠性
						测试思路
							关注Gateway Pod重建、节点漂移、滚动升级期间业务恢复。
						测试覆盖
