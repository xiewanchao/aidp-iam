三、按测试用例整理的验证记录

1. GW-TC-026 请求超时策略生效后慢请求被 Gateway 终止

测试目标：
验证 `HTTPRoute.rules[].timeouts.request` 和 `backendRequest` 生效，慢请求会被 Gateway 主动终止。

测试配置：
公共准备阶段创建的 `policy-test-route` 已包含以下配置：

```yaml
rules:
- matches:
  - path:
      type: PathPrefix
      value: /delay
  timeouts:
    request: "1s"
    backendRequest: "1s"
```

执行命令：

```bash
curl -s -H "Host: policy.local" \
  -o - \
  -w '\nHTTP %{http_code} time %{time_total}\n' \
  http://localhost:30080/delay/3
```

执行结果：

```text
upstream request timeout
HTTP 504 time 1.209651
```

测试结论：
后端延迟 3 秒，Gateway 在约 1.2 秒返回 HTTP 504，慢请求没有等待后端完成。请求超时策略验证通过。


2. GW-TC-027 请求次数限制策略达到阈值后触发限流

测试目标：
验证 `BackendTrafficPolicy.rateLimit` 能够限制目标路径请求频率，超过阈值后返回限流响应。

测试配置：
对 `policy-test-route` 的 `/get` 路径设置本地限流，阈值为 `1 request / Second`。

执行命令：

```bash
kubectl apply -f - <<'EOF'
apiVersion: gateway.envoyproxy.io/v1alpha1
kind: BackendTrafficPolicy
metadata:
  name: policy-test-rate-limit
  namespace: aidp-gateway
spec:
  targetRefs:
  - group: gateway.networking.k8s.io
    kind: HTTPRoute
    name: policy-test-route
  rateLimit:
    type: Local
    local:
      rules:
      - clientSelectors:
        - path:
            type: PathPrefix
            value: /get
        limit:
          requests: 1
          unit: Second
EOF

sleep 5

for i in 1 2 3 4; do
  curl -s -H "Host: policy.local" \
    -o /dev/null \
    -w "req${i} HTTP %{http_code}\n" \
    http://localhost:30080/get
done
```

执行结果：

```text
backendtrafficpolicy.gateway.envoyproxy.io/policy-test-rate-limit created
req1 HTTP 200
req2 HTTP 429
req3 HTTP 429
req4 HTTP 429
```

测试结论：
阈值内请求返回 HTTP 200，超过阈值后返回 HTTP 429。请求次数限制策略验证通过，可作为基础 DDoS 防护能力验证。


3. GW-TC-028 请求 IP 白名单策略只允许白名单来源访问

测试目标：
验证 `SecurityPolicy.authorization` 配置为白名单模式时，只允许匹配 CIDR 的来源访问目标路由。

测试准备：
先删除限流策略，避免影响白名单测试。

执行命令：

```bash
kubectl -n aidp-gateway delete backendtrafficpolicy policy-test-rate-limit --ignore-not-found=true
```

执行结果：

```text
backendtrafficpolicy.gateway.envoyproxy.io "policy-test-rate-limit" deleted
```


3.1 白名单匹配场景

测试配置：
`defaultAction: Deny`，只允许 `0.0.0.0/0`，当前请求来源应匹配。

执行命令：

```bash
kubectl apply -f - <<'EOF'
apiVersion: gateway.envoyproxy.io/v1alpha1
kind: SecurityPolicy
metadata:
  name: policy-test-ip-policy
  namespace: aidp-gateway
spec:
  targetRefs:
  - group: gateway.networking.k8s.io
    kind: HTTPRoute
    name: policy-test-route
  authorization:
    defaultAction: Deny
    rules:
    - name: allow-all-test-client
      action: Allow
      principal:
        clientCIDRs:
        - 0.0.0.0/0
EOF

sleep 4

curl -s -H "Host: policy.local" \
  -o /dev/null \
  -w "whitelist-allow-all HTTP %{http_code}\n" \
  http://localhost:30080/get
```

执行结果：

```text
securitypolicy.gateway.envoyproxy.io/policy-test-ip-policy created
whitelist-allow-all HTTP 200
```

结论：
白名单匹配时，请求被放行。


3.2 白名单不匹配场景

测试配置：
仍使用 `defaultAction: Deny`，但只允许 `203.0.113.0/24`，当前请求来源不匹配。

执行命令：

```bash
kubectl apply -f - <<'EOF'
apiVersion: gateway.envoyproxy.io/v1alpha1
kind: SecurityPolicy
metadata:
  name: policy-test-ip-policy
  namespace: aidp-gateway
spec:
  targetRefs:
  - group: gateway.networking.k8s.io
    kind: HTTPRoute
    name: policy-test-route
  authorization:
    defaultAction: Deny
    rules:
    - name: allow-non-matching-cidr
      action: Allow
      principal:
        clientCIDRs:
        - 203.0.113.0/24
EOF

sleep 4

curl -s -H "Host: policy.local" \
  -o /dev/null \
  -w "whitelist-nonmatch HTTP %{http_code}\n" \
  http://localhost:30080/get
```

执行结果：

```text
securitypolicy.gateway.envoyproxy.io/policy-test-ip-policy configured
whitelist-nonmatch HTTP 403
```

测试结论：
白名单匹配时返回 HTTP 200，白名单不匹配时返回 HTTP 403。请求 IP 白名单策略验证通过。

1、GW-TC-026 请求超时策略：
验证通过。后端延迟 3 秒时，Gateway 在约 1.2 秒返回 HTTP 504。

验证通过。配置 1 request / Second 后，连续请求第 1 次返回 HTTP 200，后续请求返回 HTTP 429。

3、GW-TC-028 请求 IP 白名单策略：
验证通过。允许 `0.0.0.0/0` 时返回 HTTP 200；只允许不匹配 CIDR `203.0.113.0/24` 时返回 HTTP 403。

4、GW-TC-029 请求 IP 黑名单策略：
验证通过。拒绝 `0.0.0.0/0` 时返回 HTTP 403；拒绝不匹配 CIDR `203.0.113.0/24` 时返回 HTTP 200。

5、测试资源清理：
验证通过。临时 namespace、HTTPRoute、SecurityPolicy、BackendTrafficPolicy 均已删除。
